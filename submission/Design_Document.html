1. Architectural Overview & Design Philosophy

The system implements a decoupled, event-driven multi-agent architecture specifically engineered to eliminate factual hallucination and unverified assertions in autonomous research synthesis.

Rather than relying on a brittle chain-of-thought prompt in a single execution context, the platform partitions research into five specialized roles operating across a shared state blackboard:

2. Detailed Station Specifications

Station 01: Strategic Planner (`PlannerAgent`)

  • Input: Research topic, target depth (quick | standard | deep), target persona (executive | academic | technical).
  • Output: ResearchPlan object containing deconstructed sub-questions, working hypotheses, and initial search query vectors.
  • Adaptive Capability: Can dynamically update active working hypotheses in shared run memory upon receiving a gap critique from the Epistemic Critic.

Station 02: Scout Searcher (`SearcherAgent`)

  • Input: Initial search query vectors from Planner OR refined targeted queries from Critic replanning loop.
  • Tools Invoked: WebSearchTool (DuckDuckGo instant & live HTML fallback, Wikipedia API, academic indices).
  • Output: Deduplicated array of SearchSource records with domain authority tags.

Station 03: Deep Reader (`ReaderAgent`)

  • Input: Discovered source documents and user-provided vault documents.
  • Tools Invoked: DocumentParserTool, Regex quantitative extractor.
  • Output: Array of structured ExtractedFact objects categorized as statistic, finding, or quote.

Station 04: Epistemic Critic (`CriticAgent`)

  • Input: Research plan, source candidate list, and extracted facts bank.
  • Core Rubric: Computes domain authority scorecards (0-100), flags unverified claims, identifies information gaps, and stress-tests hypotheses.
  • Evaluator-Optimizer Gate:
    • If overallCredibilityScore < 80 OR informationGaps.length > 0: Sets criticDecision = 'request_more_evidence' and generates targeted followUpSearchQueries.
    • If evidence is sufficient: Emits criticDecision = 'approved' and authorizes Stage 05 synthesis.
  • Red Team Adversarial Module: Actively identifies worst-case operational risks, supply-chain bottlenecks, and counter-theses.

Station 05: Executive Synthesizer (`WriterAgent`)

  • Input: Audited facts, approved sources, persona styling directives, and synthesis guidance from Critic.
  • Output: Publication-grade whitepaper rendered in Markdown with bracketed footnote citations ([^1]), Executive Summary, Comparative Matrix, and Bibliography.

3. State Machine & Memory Management

Memory Component State Scope Data Structures & Mutability
verifiedFacts Run-scoped Array of facts confirmed with confidence ≥ 0.70. Append-only during replan loops.
rejectedSources Run-scoped Sources failing domain authority or flagged for commercial bias by Critic.
activeHypotheses Dynamic Initial hypotheses formulated by Planner, refined when Critic detects critical gaps.
replanHistory Audit Log Sequential record of loops containing from, to, reason, queryBefore, queryAfter, scoreBefore, scoreAfter.
messageBus Pub/Sub In-memory event stream transmitting typed messages (task, result, critique, status).

4. UI Design System: Apple Liquid Glass Dark Theme

  • Color Palette: Deep obsidian base (#07080F to #0B0D1A) with ambient blurred violet/cyan/magenta orbs.
  • Frosted Glass Tokens: backdrop-filter: blur(20px) saturate(160%), 1px white border with 12% alpha, subtle inner top edge highlight, and soft multi-elevation drop shadows.
  • Agent Station Edge Accents: Station 01 Violet (#7C5CFF), Station 02 Cyan (#06B6D4), Station 03 Amber (#F59E0B), Station 04 Red (#EF4444), Station 05 Fuchsia (#A855F7).
  • Typography: Inter for high-readability body UI, JetBrains Mono for telemetry, counters, and execution traces. Meets WCAG AA contrast standards.

5. Testing & Verification

The system guarantees deterministic execution through Vitest suites:

  • tests/criticFeedbackLoop.test.ts: Proves non-linear multi-agent feedback wherein Critic rejection forces Scout re-query and Planner hypothesis evolution.
  • tests/orchestrator.test.ts: Validates end-to-end 5-station execution and execution trace generation.
  • tests/tools.test.ts: Verifies search and document parsing tools with deterministic fallbacks.
